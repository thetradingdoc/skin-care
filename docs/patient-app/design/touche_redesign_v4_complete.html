v4.1 — what this "final" actually covers, and what it doesn't

This is the final visual + journey SSOT for Wave 0–2 chrome (35 frames now, after adding the missing Photo/Upload step and expanding Tag to the real 6-tag model). It is not verified against live app routes — that verification is Phase A's Playwright baseline, not something a static mock can prove. The Region picker frame is explicitly marked pending that confirmation, not silently treated as resolved.
Fixed in this pass, per Cursor's gap review
  • Added the Photo/Upload capture-entry frame that was missing — Track hub was jumping straight to Tag picker, skipping the actual first step
  • Tag picker expanded from 4 collapsed groups to the real 6 tags (skin, mark, prescription, lab, bill, other) — matches the API instead of a simplified visual grouping
  • Region picker now explicitly flagged as visual-intent-only pending route confirmation, not presented as already wired
Decided, not left open
  • OPQRST + routine nudge: keep, restyle into v4 language — dropping them from the spine was an oversight, not a product decision
  • Alerts → shop/verdict paths: stay claim-safe-gated, same rule as everywhere else
What changed vs v3, and open items
Every point from your last review, addressed
  • Real tulip mark (exact SVG path), colored to match context — white on the red hero, red on white screens
  • "Be Bold." centered with tulip inline before it, matching your reference lockup
  • Welcome copy replaced exactly as specified
  • Get Started button now solid #E31919
  • Tab icons rebuilt as recognizable line-icon metaphors — calendar grid, bottle (Shelf), trending line (Progress), person (Profile) — no more ambiguous glyphs
  • Track FAB is one solid red circle, white ring, white center dot, matching your screenshots exactly
  • Track hub is white now — red lives only in the FAB and accents
  • Flow order corrected: Tag picker before Region picker; region only appears for skin/mark
  • Back-nav header added to every non-root screen in this file
  • Routine/PIH: v1 scope confirmed as B — "Why are you here" persona picker in onboarding, plan preview screen with rewritten claim-safe copy, plan-context card on Progress. Scheduled milestone-facts (Phase 2/model A) intentionally not built here.
  • Claim-unsafe phrasing rewritten throughout — "what this plan typically involves," "habits, not promises," explicit no-timeline-promised disclaimers replacing the JSON's original "expect visible improvement by week N" language
New: billing/pricing section

Added because it was flagged as completely missing. Framed per your "tool-first" instruction: Care Program checkout copy explicitly states "this is not medical treatment and does not replace a dermatologist" — matches the claim-safe requirement while still selling the tracking tool clearly.

Backend reality check, not a design problem: prod Stripe Price IDs (Care Program, Plus, credit pack) are confirmed unset on the current serving revision. These screens can be built in Cursor today, but checkout will fail until those are configured — that's an ops task, not blocked by this file.
Still open, flagged not silently dropped
  • Font: Poppins stands in for "Garet" pending licensing/asset confirmation
  • iOS review risk: Care Program still routes through Stripe web checkout, same class of risk already flagged for Unlock-AI — worth a decision before submission, not a redesign question
  • Template-shared, not redrawn: camera-denied/vision-fail/manual-entry, confirm for bill/rx/lab/other tags, Get-the-app interstitial — same chrome as screens shown, fields/copy swap per tag
