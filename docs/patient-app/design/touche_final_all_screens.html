touche — medical tracker: full IA rebuild (v8)

Rebuilt around the new 5-tab structure (Calendar / Shelf / Track / Progress / Profile), reordered onboarding, and the manual-free / AI-metered monetization model. Reuses the same color/type/component tokens as v7 — nothing about the visual language changed, only the structure.

Tab definitions (what each tab is for — not screen-by-screen, the job of the tab)

Calendar — the journal. Everything ever logged, any type, by date. Templates/routines are chosen from here, not at onboarding.

Shelf (was Shop) — inventory of products and medications. Ask a question against something on the shelf, buy (contextual, Shopify), learn. Commerce lives here, framed as inventory, not a storefront.

Track (center, raised) — the one capture action. Photo or upload, any type — skin, prescription, bill, other. Routes into tagging, then the shared confirm/edit flow.

Progress — personalized analytics, functions as the home/summary. Self-reported skin trend (never fabricated %), bill totals if tracked, upcoming reminders (Rx expiring, etc).

Profile — consent, share-with-doctor export, routine management, subscription/credits, delete.

Onboarding sequence (explicit — gate item 7)

0 Welcome → 1 Consent → 2a Capture (or 2m manual / 2b denied / 2c fail) → 3 Tag → 4 Loading → 5-[tag] Confirm → 5b-[tag] Reveal → 6-[tag] Thesis → 9 OPQRST-lite (skin-tag only, skippable) → 10 Routine nudge (skin-tag only, one-time, skippable) → 7 Auth (name+OTP) → 7b/7c OTP → 8 Get the app → lands on Progress (T9)

9 and 10 sit before auth, only in the skin-tag path, and only once. A bill/Rx/mark/lab/other tag skips 9 and 10 entirely and goes straight from 6 to 7.

Canonical tag enum (gate item 2) — six, everywhere, no exceptions

skin | bill | prescription | mark | lab | other

Must appear identically on: Tag screen (3), Manual form (2m), Calendar legend, Confirm template selection. If a screen shows fewer than six, that screen is wrong, not the enum.

Per-tag fact set (the actual data contract — gate item 3)

skin — date, body area, note, AI suggestion (labeled AI, separate from user confirm)

bill — date, provider, amount, currency, doc type

prescription — drug, strength, prescriber, date, expiry, refill-reminder opt-in

mark — date, body location, note, photo ref, compare_group_id (links repeat photos of the same mark for compare-over-time)

lab — date, provider, title, source_language (detected, editable), display_language (preference), structured results where extractable, else free-text

other — date, free-text label, free-text facts

Cross-cutting on every record: media_type (photo | pdf — video explicitly not in v1, UI must say so, not imply it), ai_or_manual (hard rule 3 — every AI-derived value labeled distinctly from user-entered).

Hard rules carried over + new for this round

1–4 (describe never diagnose, loading only real steps, AI vs self-reported labeled, manual escape always one tap) unchanged from v5–v7.

5. No correlation/impact-% UI. 6–8: any record capturable, derm insight only, type badges — unchanged.

9. Manual entry is always free and unmetered. Only AI-assisted capture (vision/OCR call) counts against the monthly meter.

10. First-week backfill allowance is separate from the recurring monthly meter — shown explicitly to the user, expires, doesn't silently blend into month one's count.

11. Password is not in this round — auth stays OTP + name only. Do not design a password-creation screen.
